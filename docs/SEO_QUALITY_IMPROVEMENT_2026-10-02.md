## 2. 사이트 정체성

상위 개념은 **“생활의 숫자를 계산하고, 집안의 문제에 맞는 방법을 찾는 곳”**이다. 숫자로 비교·예측할 수 있는 문제에는 계산기를, 소재·제품·상황에 따라 방법을 골라야 하는 문제에는 생활백과를 둔다. 기존 가이드는 계산 결과의 전제와 판단을 돕는다. 두 영역을 억지로 같은 기능이라 부르지 않고 **판단을 돕는 서로 다른 형식**으로 설명한다.

| 요소 | 이전 | 현재 적용 |
|---|---|---|
| 홈 H1 (ko) | “오늘 뭐 계산해볼까요?” | “생활의 숫자를 계산하고, 집안의 문제를 해결하세요” |
| 홈 소개 (ko) | 장보기·전기요금·급여·판매 마진의 계산만 안내 | 가격·비용은 직접 계산하고 얼룩·세탁·청소는 상황에 맞는 방법을 찾도록 안내 |
| About | 돈 관련 계산기와 그 기준만 설명 | 계산기·생활백과의 역할과 제품 라벨 우선 원칙을 함께 설명; 현재 부족한 출처를 과장하지 않음 |
| 사이트 description | 무료 계산기 모음 | 계산기와 가정의 문제 해결 안내를 함께 설명 |
| WebSite / Organization | WebSite 이름·URL·언어만 있고 Organization 별도 설명 없음 | 각 언어의 새 사이트 description을 두 타입에 넣음. 실재하지 않는 전문가·법인 정보는 넣지 않음 |
| 계산기 영역 | 전부 브라우저 계산만 설명 | 숫자로 판단할 때의 입력·공식·결과 설명을 강조 |
| 생활백과 영역 | 집안일을 쉽고 빠르게 해결한다고 설명 | 소재와 상황에 따라 다른 순서를 고르도록 설명 |

영어와 일본어에도 각 언어로 같은 서비스 목적을 설명한다. 검색어 나열을 위해 단어를 반복하지 않았다. 계산기 입력은 기존대로 브라우저 안에서만 처리한다.

## 3. 신뢰 정보와 출처 구조

새 `/ko|en|ja/editorial-policy`는 작성 범위, 정부·공공기관과 제조사 원문 우선, 적용 국가·연도·모델, 기준일, 세정제·소재별 차이, 계산 함수 테스트, 수정일, 오류 제보를 설명한다. **과거 글 전체가 이미 이 원칙대로 검증됐다고 말하지 않는다.** 현재 페이지 저자를 개인 전문가로 바꾸거나 경험을 지어내지 않았다. 문의는 기존 사이트 설정의 이메일을 사용한다.

기존 `SourceRef {label, url?}`에 `publisher?`, `accessedAt?`를 추가했다. 기존 콘텐츠와 호환된다. URL이 있는 항목만 클릭 가능한 출처로, URL 없는 항목은 “제품·자료 확인 안내”로 보인다. **한 페이지에 링크가 있어도 모든 주장에 근거가 생긴 것은 아니다.** 원문이 뒷받침하는 문장을 사람이 별도로 확인해야 한다.

## 5. 내부링크와 허브

변경 전 생활백과 상세의 직접 계산기 링크는 한국어 50편 중 15편에서 16개, 영어·일본어 각 0개였다. 변경 후는 **한국어 2편에서 2개**, 영어·일본어 0개다. 남긴 흐름은 `ko/condensation → ko/heating-cost`(난방을 조정할 때 비용 확인), `ko/balcony-mold → ko/wallpaper`(원인 해결 뒤 벽지 교체를 결정한 경우의 필요량 계산)이다. 후자는 곰팡이 치료 도구처럼 소개하면 부적절하므로 후속 콘텐츠 검토 때 교체 조건을 더 분명히 할 필요가 있다. 계산기에서 돌아오는 관련 글 카드도 같은 선언에서 생성된다.

에어프라이어·가습기·세탁기 청소에서 가전 전기료로 가는 추천, 욕실·창틀 곰팡이에서 벽지 필요량으로 바로 가는 추천은 없앴다. 에어컨 청소 일본어 글에서 한국어 전용 에어컨 전기료 계산기를 가리키던 선언도 없앴다. 영어·일본어에 현재 해당 의사결정에 적합한 계산기가 없으므로 링크 0은 누락을 억지로 메울 문제가 아니다. 관련 생활 글은 주방 기름때·신발 냄새·실내 건조 등 다음 행동과 가까운 것으로 일부 교체했다. 내부링크 수 감소는 이 작업의 의도이며, 사이트 전역 탐색·카테고리 연결은 유지된다.

보관 허브는 각 언어 2편이지만 빈 목록이 아니고 “계절옷인가 침구인가”를 선택하는 역할이 있다. **선택: 현재 유지.** 3개 언어의 허브 본문에 선택 기준을 추가했다. 신규 글 수를 채우기 위한 보관 콘텐츠 추가, 상위 카테고리 통합, 리다이렉트는 현 단계에서 하지 않는다. 한국어 생활백과 카테고리 허브 7개가 9월 23일 미색인이었다는 커밋 기록은 참고하되, 현재 색인 상태와 동일하다고 가정하지 않는다. 각 허브는 글 수보다 사용자가 문제 유형을 빠르게 구분할 수 있는지로 후속 검토한다.

## 6. 우선 개선 20개와 보류 범위

[20개 URL별 실행표](SEO_PRIORITY_20_2026-10-02.csv)는 요청한 **URL / 현재 문제 / 개선 내용 / 필요한 출처 / 내부링크 개선 / 콘텐츠 구조 개선 / 우선순위** 7개 필드와 이번 적용 상태를 담는다. 핵심 계산기, 9월 커밋에 기록된 Search Console 사례, 근거가 중요한 생활 글, 당시 미색인 허브를 섞었다. 원래 우선순위의 Search Console 수치는 당시 커밋 메시지의 기록이며, 현재 상태를 뜻하지 않는다.

P0에서 먼저 검토할 순서는 ① 법정 요율·전기요금 계산기 기준값과 원문 일치 ② 제품에 따라 위험이 달라지는 청소·세탁 문장 ③ 해당 주제의 검색 의도에 맞는 답과 예시다. 20개 모두를 이번에 고친 것은 아니다. 1차에서는 공식 문서와 대조한 본문 2편, 보관 허브 3개 언어를 고쳤고, 추가 실행은 8절에 기록했다.

**보류:** 페이지 삭제, noindex, 리다이렉트, 카테고리·URL 통합, locale 구조 변경, 150편 일괄 재작성, 존재하지 않는 출처나 자격 표시, 공식 확인 전 제도 기준값 수정. Google 색인 제외 건수를 줄이기 위한 기계적 조치도 하지 않는다.

## 7. 배포 전 자동 검사와 재크롤링 후 확인

`npm run verify`에 다음을 연결했다.

| 검사 | 실행 내용과 한계 |
|---|---|
| `check:site` | 기존 깨진 링크·H1·기본 메타·비밀키 검사에 공개 페이지의 내부 유입 링크, self canonical, noindex, hreflang 상호 연결, 사이트맵 경로 일치를 추가. 의미상 링크가 좋은지는 판단 못함 |
| `check:urls` | 검토 시점 288개 경로와 빌드 사이트맵을 비교. **288 +3 −0 =291**; 10개 이상 증가·감소하면 경고. 기준은 현재 배포 상태라는 보장이 아니라 이번 변경 직전 스냅샷이며, 실제 배포 확인 후에만 갱신 |
| `check:sources` | 숫자·단위가 있고 원문 링크가 없는 파일을 검토 후보로 기록; 직접 입력된 비 HTTPS URL은 실패. 문장별 출처 적합성과 외부 링크의 생존은 사람 검토 필요 |
| `check:topic-links` | 생활백과→계산기 추천 선언과 언어별 실제 표시 여부를 JSON으로 보고. 주제 관련성은 편집 검토 필요 |

같은 H2 배열의 반복률이나 본문 길이는 기계적으로 셀 수 있으나, 그것만으로 품질이 낮다고 판정할 수 없다. 초기 감사의 150편 공통 배열은 알려진 검토 대상으로 유지하고, 앞으로는 유형별 본문 심사와 실제 원문 대조를 통해 판단한다.

Google 재크롤링 후에는 **원본 Search Console에서** 기존 114개와 신규 174개를 구분하여 일별 색인 상태·노출·평균 순위·질의를 본다. 새 편집 원칙 3개 URL의 크롤·색인 여부도 확인하되 그 자체가 회복 지표는 아니다. 특히 기존 계산기에서 같은 국가·기기·질의의 노출이 돌아오는지, 수정한 2개 생활 글과 보관 허브가 재크롤되었는지, “크롤링됨·미색인” 115개 내역이 어떤 URL에서 변했는지 확인한다. 검색 노출 변화는 배포 직후가 아니라 Google의 재처리 뒤 나타날 수 있고, 이번 수정과 무관한 수요·경쟁 변화도 함께 대조해야 한다.
