작성일: 2026-10-02. 범위: 저장소 Git 이력, 현재 소스와 정적 빌드 HTML 288개, 이전 기술 SEO 전수 검사 결과, 사용자가 제공한 Search Console 수치. 코드·색인 설정은 변경하지 않았다. 전체 URL과 신규 URL별 A/B/C/D 판정은 [URL 목록 CSV](SEO_URL_INVENTORY_2026-10-02.csv)에 있다.

## 1. 결론과 증거의 경계

생활백과 174개 URL을 약 7시간 30분 사이에 추가하여 사이트의 60.4%로 만든 것은 9월 11일 전후 노출 급락의 **검토할 만한 선행 사건**이다. 그러나 현재 자료만으로 Google이 이 확장을 이유로 사이트 전체를 낮게 평가했다고 판정할 수 없다. 페이지 본문은 대체로 문제별 해결 절차와 예외를 담고 있어, URL 수나 공통 템플릿만으로 대량 생성 스팸이라고 볼 근거도 없다. 반면 출처의 검증 가능성, 실제 사용·시험 근거, 발행 주체의 전문성 설명, 기존 계산기와의 주제 연결은 약하다. 현시점 가설 판정은 **D(결정 불가)**, 후속 검증 우선순위는 **B(사이트 범위 신호)**와 **C(기존 페이지의 독립적 재평가)**이다. **A의 “신규 URL만”이라는 한정은 현 증거와 충돌할 가능성이 크다.**

8월 24일 이전 Git 커밋이 없다. 첫 커밋은 **8월 25일 10:14:36 KST**다. 따라서 “8월 24일 이전의 114개 URL”을 Git으로 증명할 수 없다. 이 보고서의 `baseline` 114개는 **생활백과 도입 직전 8월 25일 13:23:24 `af69074`**에 존재한 라우트다. 정확한 8월 24일 실배포 URL 목록은 당시 배포본·sitemap 아카이브가 필요하다. 또한 Git 커밋 시점과 실제 Vercel 배포·Google 발견 시점은 다를 수 있다.

## 3. 본문 품질: 반복성, 고유성, 검색 의도

정적 HTML의 제목·설명이 아닌 본문 문단, 목록, FAQ를 점검했다. CSV의 `same_locale_exact_block_unique_char_ratio_proxy`는 **같은 언어의 다른 상세 페이지에 정확히 같은 문장 블록으로 나타나지 않는 글자 수 / 분석한 본문 글자 수**다. 생활백과는 출처 박스와 관련 글 카드를, 계산기는 입력 UI·관련 카드·출처 박스를 제외했다. **이는 문구 중복 지표이지, 의미상 고유 정보량이나 웹 전체에 대한 독창성 점수가 아니다.** 생활백과 안전 안내 같은 공통 문구는 중복으로 잡힌다. 허브·홈 등에는 이 수치를 적용하지 않았다.

|---|---:|---:|---:|

| 기존 가이드 | 0.975 | 0.974 | 0.972 |

생활백과 한국어 페이지의 최솟값도 0.863이다. 즉 저장소 내부의 **문단 단위 복사·붙여넣기**가 주된 패턴이라고 보기 어렵다. 그러나 150개가 모두 같은 `요약 → 빠른 답 → 준비물 → 단계 → 주의 → 상황별 팁 → 원인 → 예방 → FAQ` 구조를 사용하고, 언어별 50개에서 H2 제목 배열이 동일하다. 첫 화면에서 문제와 처리 순서를 바로 답하는 장점이 있으나, 주제별로 어떤 근거·사진·실험·수치가 필요한지까지 구조가 달라지지는 않는다.

생활백과 FAQ 질문은 ko 197개 중 176개, en 218개 중 217개, ja 214개 중 211개가 서로 다르다. **질문과 답변의 정확한 쌍은 세 언어 모두 전부 고유**했다. 주의사항은 ko 289개 중 268개, en 302개 중 301개, ja 308개 중 293개가 고유했다. `얼마나 자주 청소해야 하나요?` 같은 질문과 염소계 표백제·산성 세정제 혼합 금지 문구가 반복되지만, 후자는 안전상 필요한 공통 안내다. 영어 `washing-machine-smell`과 `drum-washer-cleaning`은 같은 언어에서 가장 비슷한 쌍이었어도 7글자 조각 중복 Jaccard가 0.231이었다. 일률적 중복 페이지라고 단정할 수 없다.

**페이지에서만 얻을 수 있는 내용**은 일부 뚜렷하다. 수건 냄새 글은 극세사/면 구분과 온도·건조 대안을, 드럼세탁기와 통돌이 청소 글은 구조별 다른 순서를, 일본어 다다미 곰팡이는 물걸레를 피하고 다다미 결·건조 조건에 맞춘 절차를 제시한다. `kimchi-stain`과 `gochujang-stain`도 색소와 점성 차이를 설명한다. 기존 계산기는 사용자가 입력한 값에 따른 실제 계산 결과·수식·예시가 핵심 효용이다. 그 설명만으로 계산 의도를 충족하는 페이지도 많다. 다만 9월 23일 추가된 한국어 실계산 조견표는 **9월 11일 당시 콘텐츠의 장점으로 소급할 수 없다.**

**약한 지점은 검증 가능성**이다. 150개 생활백과 파일은 모두 `sources`에 한 줄 안내가 있지만 실제 출처 URL은 0개다. `제품 라벨/설명서를 확인하세요`는 유용한 안전 단서이나, `60℃`, `6시간`, 약제 농도, 재질 손상, 곰팡이 범위 같은 단정의 근거를 독자가 확인할 수는 없다. 23개 가이드는 콘텐츠 타입에 출처 필드가 없고, 55개 계산기 중 9개만 출처 항목이 있으며 URL은 3개에만 있다. 계산기는 계산 로직 자체가 차별화 요소지만 제도·요율을 다루는 페이지에는 특히 기준 날짜와 원문 출처가 중요하다. 생활백과의 작성·검수자 이름이나 직접 사용한 제품·소재의 기록은 없고, Article 구조화 데이터의 저자는 사이트 조직명이다. 소개 페이지는 사이트를 금액·경제 **계산기**로 설명하며 생활백과의 편집 영역과 전문성을 설명하지 않는다.

외부 비교는 대표 주제에 한정했다. 일본어 전기주전자 물때 글의 구연산·헹굼 흐름은 [제조사 조지루시의 청소 안내](https://www.zojirushi.co.jp/kakushiaji/article/000019/)에서도 제공한다. 영어 에어프라이어 글의 기본 세척 단계는 [제조사 Philips 안내](https://www.usa.philips.com/c-f/XC000012903/how-to-clean-my-philips-airfryer)와 겹친다. eolmaji 글은 상황별 팁을 더하지만 기종별 확인 자료나 직접 비교 실험은 제시하지 않는다. **이 표본만으로 150편이 상위 검색 결과를 재구성했다고 판정할 수 없다.** 주제·국가별 실제 Google 상위 5~10개 결과에 대한 체계적 대조가 추가로 필요하다.

## 4. ko/en/ja 비교와 로컬라이즈

54개 주제 중 48개를 세 언어로 공유한다(144 URL). 언어 전용은 한국어 `kimchi-stain`, `gochujang-stain`; 영어 `wine-stain`, `dishwasher-cleaning`; 일본어 `tatami-mold`, `aircon-cleaning` 각 2개다(6 URL). 공유 주제는 동일한 섹션 설계와 대체로 같은 해결 논리를 따르므로 **번역·각색 계열**로 표시한다. 텍스트 작성 과정이 기계번역이었는지, 사람이 검수했는지는 저장소만으로 확인할 수 없다. 번역이라는 사실 자체는 품질 문제나 정책 위반의 증거가 아니다.

영어는 `towel-smell`에서 `1 tablespoon per gallon`, `140°F / 60°C`, 산소계 표백제와 건조기 사용 등 단위·생활 맥락을 바꾸고, 영어 전용 식기세척기 글은 필터·분사암·물때 등 검색 의도를 직접 다룬다. 일본어는 `縦型洗濯機`, `梅雨`, `部屋干し`, `畳`, 에어컨 `内部クリーン`처럼 일본 사용자의 제품·주거 맥락이 들어 있다. **세 언어 전체를 기계적인 직역이라고 평할 수 없다.**

남은 검증은 현지 모델과 제조사 지침이다. 예컨대 영어 에어프라이어 글의 물·레몬/식초를 넣고 가열하는 냄새 제거 팁, 일본어 다다미 글의 습도·작업 시간, 각 언어 세탁 글의 온도·약제량은 제품/소재 조건에 따라 달라질 수 있는데 구체적인 근거 링크가 없다. 영어권도 미국·영국·호주가 같은 제품·단위 체계는 아니며, 일본어 글도 일본 제조사 모델별 차이를 충분히 인용하지 않는다. 제도 의존 주제는 생활백과보다 기존 한국어 전용 계산기에 집중되어 있어, 영어·일본어의 제도 오역이 주요 문제로 보이지는 않는다.

## 5. 주제 범위와 내부링크의 실제 관련성

확장 전 사이트는 구매·생활비·급여·판매 계산기와 그 사용 가이드가 중심이었다. 확장 후 전체 288개 중 생활백과 174개(60.4%)이며 얼룩·세탁·청소·냄새·주방·보관·주거 관리가 새 축이다. `src/lib/life/categories.ts`도 도구는 “얼마지?”, 생활백과는 “어떻게 하지?”라고 별도 축으로 정의한다. 독자에게 생활 문제 해결이라는 인접한 효용은 있지만, **사이트 소개와 기존 대표 계산기에서 청소·얼룩 전문성으로 이어지는 설명은 약하다.** 이것이 사이트 주제의 선명도를 약화했을 가능성은 있으나 Google이 실제로 그렇게 평가했는지는 별도 문제다.

링크는 존재하지만 관계가 고르지 않다. 생활백과 메타의 계산기 연결 선언은 54개 주제 중 17개 주제에 18개다. 해당 계산기 네 종류(`appliance-electricity`, `wallpaper`, `aircon-electricity`, `heating-cost`)가 **모두 한국어 전용**이고, 선언 중 일본어 전용 `aircon-cleaning`과 영어 전용 `dishwasher-cleaning`의 연결은 각 언어에서 필터링된다. 렌더된 상세 페이지에서 실제 계산기 링크는 **한국어 50편 중 15편에 16개**, 영어 50편 **0개**, 일본어 50편 **0개**다. 역방향은 한국어 계산기 3개에 총 7개 카드만 표시된다. 계산기 쪽 최대 3편 제한으로 `appliance-electricity`에 연결 선언된 생활백과 10편 가운데 3편만 노출된다. 이 수치는 허브·전역 내비게이션을 제외한 **상세 페이지의 주제별 연결**이다. 생활백과 글끼리는 카테고리와 관련 글을 통해 연결되어 있으므로 고아 페이지로 볼 수 없다.

질적으로 `condensation → heating-cost`는 난방과 결로의 의사결정에서 자연스럽다. `aircon-cleaning → aircon-electricity`도 주제상 자연스럽지만 서로 언어가 달라 실제 연결은 없다. `airfryer-cleaning → appliance-electricity`, `humidifier-cleaning → appliance-electricity`는 전기료가 청소 문제 해결의 다음 단계가 아니어서 자연성이 낮다. 곰팡이 글에서 `wallpaper` 비용 계산기로 가는 링크는 벽지를 교체하기로 한 뒤에는 유용하나, 곰팡이 진단·제거 중에는 한 단계 건너뛴 연결이다. 사이트 전체에 링크가 있어도 주제 전문성이 자동으로 이어지는 구조는 아니다.

## 7. Google 정책 해석

[Google의 scaled content abuse 정책](https://developers.google.com/search/docs/essentials/spam-policies#scaled-content-abuse)은 많은 페이지를 **주로 순위 조작을 위해** 만들고 사용자에게 실질 가치가 적은 경우를 다룬다. 생성 도구, 번역, URL 수 자체가 판정 기준은 아니다. 이 사이트에는 키워드·검색 의도 필드와 24시간 이내 대량 게시라는 위험 신호가 있고, 출처·고유 경험 신호가 약하다. 반면 150편의 실제 해결 절차·소재별 예외·각 언어의 현지 주제와 낮은 내부 문단 중복은 “가치 없는 대량 변형” 단정에 반대한다. 제작 목적과 외부 텍스트 재활용 여부도 확인되지 않았다. **현재 증거로 정책 위반이나 수동 조치를 주장할 수 없다.**

[Google의 사람 중심 콘텐츠 점검 지침](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)은 독창적 정보, 다른 검색 결과보다 더하는 가치, 검증 가능한 출처, 작성자와 사이트의 주제 집중도를 묻는다. 이 관점에서 약점은 구체적이다. [Google 순위 시스템 설명](https://developers.google.com/search/docs/appearance/ranking-systems-guide)은 페이지 단위 신호와 사이트 범위 신호가 함께 작용하며 나쁜 사이트 범위 신호가 모든 페이지를 일괄 하락시키는 것은 아니라고 설명한다. 따라서 “사이트 전체 페널티”라는 말보다 **언어·페이지 유형별 색인/노출을 분리해 검증할 가설**이 정확하다.
